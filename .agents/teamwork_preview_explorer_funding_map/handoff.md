# Handoff Report — Funding Map Graphic Investigation

## 1. Observation
We observed the following details in the codebase:
- **Funding Page Astro Route:** The `/funding` page is dynamic and has no static page file. It is rendered by `src/pages/[...slug].astro` using content fetched from WordPress:
  - `src/pages/[...slug].astro` line 68:
    ```astro
    const optimizedContent = processWordPressHtml(page.content.rendered);
    ```
- **Map Graphic in Build Output:** In `dist/funding/index.html` (lines 23 and 27), the map is rendered as a standard image wrapper:
  ```html
  <section class="wp-block-e3es-two-column db-feature db-feature--green db-feature--map-spill">
    <div class="db-feature__container">
      <div class="db-feature__content">...</div>
      <div class="db-feature__image-wrapper">
        <img decoding="async" src="http://e3es2026.local/wp-content/uploads/2026/06/static-map-600x400.png" alt="Map of Texas showing client locations" class="db-feature__image" loading="lazy">
      </div>
    </div>
  </section>
  ```
- **Image File Details:** The image `public/images/static-map-600x400.png` has a resolution of **600 x 400 pixels**, as confirmed by running the `file` command:
  ```bash
  public/images/static-map-600x400.png: PNG image data, 600 x 400, 8-bit/color RGBA, non-interlaced
  ```
- **Broken SVG Placeholders:** The SVG files in the repository contain 404/not found errors from Wikimedia Commons:
  - `public/images/texas-blank.svg`:
    ```
    File not found: /v1/AUTH_mw/wikipedia-commons-local-public.e2/e/e2/Texas_state_outline.svg
    ```
  - `public/images/texas-outline.svg`:
    ```
    File not found: /v1/AUTH_mw/wikipedia-commons-local-public.4e/4/4e/Texas_Silhouette.svg
    ```
- **Texas Region SVG Map:** An inline SVG map with region paths is defined inside `src/pages/clients.astro` at line 90:
  ```html
  <svg id="texas-map-svg" viewBox="0 0 941.76 907.17" class="texas-svg-map" xmlns="http://www.w3.org/2000/svg">
  ```
  This map is interactive but does *not* display client location pinpoints.
- **Default Image Wrapper Styles:** In `src/styles/mobile.scss` (lines 1163–1189), the `.db-feature__image-wrapper` class applies:
  - `transform: skewX(-5deg);`
  - `overflow: hidden;`
  - `clip-path: polygon(...);` (clipping content to an arrow shape).

---

## 2. Logic Chain
1. **Dynamic Page Limitations:** Because the `/funding` page is dynamic and edited via the WordPress Gutenberg editor, the rendered block generates a generic `.db-feature__image-wrapper` class. It **lacks** the modifier class `.db-feature__image-wrapper--spill` used on the homepage.
2. **Clipping & Skewing:** As a result, the default layout styles skew the image wrapper by `-5deg` and clip it using `clip-path: polygon(...)` and `overflow: hidden;`. This distorts and cuts off the map graphic.
3. **Blurry Asset:** The raster PNG file is small (600x400px) and scaled up to 400px height. Because of the scale factors and lack of vector properties, it appears pixelated and blurry on standard/high-DPI screens.
4. **SVG Source Gaps:** No valid SVG vector version of the client map (showing location dots) exists in the repository. The only SVG files present are broken placeholders.
5. **CSS Resolution:** By utilizing the section container's `.db-feature--map-spill` class, we can override the image wrapper rules in SCSS directly, removing the skew, disabling the clip-path, and scaling the container/image to produce a perfect 10% overlap top and bottom.

---

## 3. Caveats
- We did not connect to the live staging backend (`http://e3es2026.local`) to preview database edits. The investigation is based strictly on the static files and built production files in `dist/`.
- Visual proof of the overlap is dependent on running the build command after the proposed CSS fixes.

---

## 4. Conclusion
- The blurry image file is `static-map-600x400.png`.
- There is no SVG equivalent of the client map currently in the repository. It must be generated by exporting the vector map with client pins from Figma/Illustrator as `static-map.svg` and placing it in `public/images/`.
- A CSS strategy to prevent clipping and achieve a 10% top/bottom overlap has been designed. It uses nested selectors under `.db-feature--map-spill` to fix the missing `--spill` class in dynamic WordPress blocks.

### Proposed CSS Patch:
Add the following nested styling rule inside `src/styles/mobile.scss` (replacing the previous `.db-feature--map-spill` block around line 1326):

```scss
/* Map spill overrides for funding page and home page */
.db-feature--map-spill {
    overflow: visible !important;
    z-index: 10;
    position: relative;

    // Force override wrapper styles when nested inside the map-spill section
    .db-feature__image-wrapper {
        transform: scale(1.2) !important; // Scale by 1.2 creates 10% overflow top & 10% bottom
        clip-path: none !important;        // Prevent clipping by the arrow polygon clip-path
        overflow: visible !important;      // Allow image to overflow container bounds
        z-index: 10;
        height: 400px;

        // Counter-correct image transform to remove skew
        .db-feature__image {
            transform: none !important;    // Remove default counter-skew & zoom
            object-fit: contain !important; // Prevent map distortion
        }
    }
}

@media (max-width: 768px) {
    .db-feature--map-spill {
        .db-feature__image-wrapper {
            height: 300px;                 // Mobile height adjustment
        }
    }
}
```

---

## 5. Verification Method
1. **Apply the patch** in `src/styles/mobile.scss`.
2. **Run the build script** `npm run build` or `sync-styles.js` (if applicable) to generate the CSS.
3. **Verify the output** inside `dist/funding/index.html` and visually in the browser (if dynamic site is active):
   - The map of Texas must not be slanted/skewed (all text on the map is horizontal).
   - The map boundaries must not be clipped by the default arrow polygon.
   - The map height must be 480px (120% of 400px wrapper height), overflowing 40px (10%) beyond the top border and 40px (10%) beyond the bottom border of the section container.
